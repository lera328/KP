## Диаграмма 4. Последовательность — Смарт-отработка пропуска

```mermaid
sequenceDiagram
    actor Преподаватель
    actor Родитель
    participant UI as Веб-интерфейс
    participant Backend
    participant DB
    participant Telegram

    Преподаватель->>UI: указывает время и предпочтительные локации на неделю
    UI->>Backend: отправить доступность преподавателя
    Backend->>DB: создать свободные слоты отработки
    DB-->>Backend: слоты сохранены
    Backend-->>UI: опубликовать свободные слоты

    Родитель->>UI: открыть доступные слоты
    UI->>Backend: запросить слоты ребёнка
    Backend->>DB: проверить факт пропуска и получить свободные слоты
    DB-->>Backend: пропуск подтверждён + список слотов
    Backend-->>UI: показать слоты для записи

    Родитель->>UI: выбрать слот и нажать «Занять»
    UI->>Backend: занять выбранный слот
    Backend->>DB: отметить слот как занятый и скрыть из выдачи
    DB-->>Backend: слот успешно занят
    Backend-->>UI: подтверждение записи
    Backend->>Telegram: отправить подтверждение родителю
    Telegram-->>Родитель: «Запись на отработку подтверждена»
    Backend->>Telegram: отправить уведомление преподавателю
    Telegram-->>Преподаватель: «Назначена отработка: [дата, время, локация]»
```

## Диаграмма 9. Последовательность — Недельный цикл ленты проектов

```mermaid
sequenceDiagram

    actor Пользователь
    participant UI as Веб-интерфейс
    participant Backend
    participant DB

    Планировщик->>Backend: запуск еженедельного обновления ленты
    Backend->>DB: удалить проекты прошлой недели из ленты
    Backend->>DB: выбрать новые проекты за неделю
    Backend->>DB: опубликовать новые проекты в ленте
    DB-->>Backend: лента недели сформирована
    Backend-->>UI: обновить ленту проектов

    loop В течение недели
        Пользователь->>UI: открыть ленту и поставить лайк
        UI->>Backend: отправить лайк проекту
        Backend->>DB: сохранить лайк и обновить счетчик
        DB-->>Backend: лайк сохранен
        Backend-->>UI: обновить число лайков
    end

    Планировщик->>Backend: завершение недели
    Backend->>DB: определить проект-победитель по лайкам
    Backend->>DB: начислить победителю очки опыта
    Backend->>DB: пометить проект как «лучшая работа недели»
    DB-->>Backend: победитель сохранен
    Backend-->>UI: показать блок «Лучшая работа недели»
```

## Глава 2. Выбор программных решений и технологии разработки

### 2.1 CASE-средства для проектирования

- **Visual Studio Code** – текстовый редактор для работы с кодом, markdown и диаграммами.
- **Mermaid.js** – создание диаграмм (UML, DFD, IDEF0) в текстовом формате.
- **DBeaver / pgAdmin** – визуальное проектирование и администрирование схемы базы данных PostgreSQL.
- **Docker Desktop** – контейнеризация и локальное развертывание приложения.
- **GitHub** – хранение кода, контроль версий и совместная разработка.

### 2.2 Стек серверной части

- **Python 3.10+** – язык для разработки логики приложения.
- **Django + Django REST Framework** – веб-фреймворк и REST API.
- **PostgreSQL** – реляционная база данных.
- **Celery** – выполнение асинхронных задач (отправка уведомлений, генерация PDF).
- **ReportLab** – генерация PDF-портфолио.

### 2.3 Стек клиентской части

- **React** – библиотека для пользовательского интерфейса.
- **Fetch API** – взаимодействие с серверным API.
- **Bootstrap / CSS** – стилизация интерфейса.
- **Chart.js** – отображение статистики и графиков.

### 2.4 Инфраструктура

- **Nginx** – веб-сервер и обратный прокси.
- **Docker** – контейнеризация приложения для локальной разработки.
- **Git / GitHub** – контроль версий и хранение кода.

### 2.5 Внешние интеграции

- **Telegram Bot API** – отправка уведомлений.
- **PostgreSQL с JSON** – гибкое хранение данных.
- Локальное файловое хранилище для портфолио и документов.
